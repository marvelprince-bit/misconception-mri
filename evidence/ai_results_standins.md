# AI rule-writer results with stand-in writers (no live model)

Generated by `python scripts/evaluate_ai.py --writer <name> --seeds 20` on commit 0fa4b47. One wrong rule is removed from the tool's list and a simulated student follows it. The AI is only called when no known rule fits.

- **oracle** writes the true rule (what a good model should do).
- **cheat** memorises the answers it was shown and does correct maths everywhere else (what the hidden-answer check exists to catch).
- **down** behaves like an AI service that cannot be reached.
- **messy** has the right idea but sloppy formatting (```py fence, type hints, text after the code); it fixes the code when asked to repair it.
- **partial** reproduces the failure found in the live Claude run: it copies the student's rule only on the kinds of question where it saw wrong answers and does correct maths elsewhere (integers only).

The last table is the same partial writer with the shape check switched off (`--shape-check none`), i.e. the design before the fix.

"final_wrong_pct" of 8.1% (all topics) or 9.3% (integers) in every row comes from sessions where the engine named another KNOWN rule before the AI was ever called.
